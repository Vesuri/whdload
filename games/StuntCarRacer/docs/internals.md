# Internals

## Loading

The slave (`ws_BaseMemSize` $80000, an optional $70000-byte ExpMem) has two paths.

- **Disk** (`Disk.1`): it loads the intro, $9800 bytes from disk offset $2c00, to $59e8.
  On the original disk that starts `bra` ($6000007a) and is Rob Northen encrypted: the slave
  decrypts $22b6 longwords from +$c98 and moves them down to $59e8. The intro is patched
  (`_PL_Intro`) and run. Its loader is replaced by `_Loader`, which reads the main program
  ($dc00 on the disk, loaded to $e700) with `resload_DiskLoad`. Before the main program runs,
  `_PatchMain` decrypts it the same way ($18ef8 longwords, three keys from Harry) and moves it
  down to $e700, clearing the $c9c bytes left at its end; a cracked disk is already plain.
- **TNT** (`SCR-TNT` present): the executable is loaded to $1000 and relocated. Its loader
  copies a patch to $7e000, which the slave copies into ExpMem instead (to $7e000 when there
  is no ExpMem); then it jumps to
  `_TNTSpecific`, which turns the track preview's reds to blues and joins the disk path's
  `_GameCommon` at $e700.

Both then apply `_PL_Game` to the program and move the game's two stacks to ExpMem+$1000
(they stay in chip memory without ExpMem). The program is the one at $e700, or with the
enhanced framerate its copy in ExpMem (below).

The main program must start `movea.l #$e730,a0` ($207c0000) once decrypted (or on a cracked
disk); anything else ends with WHDLoad's wrong-version requester.

## The fast copy (CUSTOM3, 68020 or better)

With CUSTOM3 on a 68020 or better and the ExpMem there, `_Enhance` copies the program
($e700-$722e0) to ExpMem+$1000 and adds the copy's distance from $e700 to every absolute
reference the program makes to itself, then `_PL_Game` patches the copy and the game starts
there. The chip copy stays as it was: nothing runs from it, and what the hardware reads stays
in chip memory at the original addresses, so references to it are not relocated:

| Chip memory | What |
|---|---|
| $e74e-$e836 | the copper list |
| $f4b4-$1b6ca | the empty sprite and the samples |
| $6a594- | the frame buffers |

`src/relocs.s` (`relocTable`) lists the 5995 sites. It is generated by
`tools/unleashed_diff.py` (development.md) from Stunt Car Racer Unleashed 1.1, the reassembled
game, whose relocation table names each reference the original makes: every reference
Unleashed relocates to its code, its copy of the original data or its own data and BSS,
where the original holds an address in the program, and the pointer tables of its Data
section (the mountain shapes, the result pictures), placed in the original through their
labels. On top of that, the original code is
scanned, both linearly and by recursive descent from the start and every call target (the
game keeps flags in its instruction stream, which a linear disassembly misreads), for the
references Unleashed rewrote or dropped: the interrupt vectors, self-modifying code, the
copylock's checks. The tool's `NOT_ADDRESSES` lists the constants that look like
addresses, and `EXTRA_SITES` the one address computed from outside the program (the
copylock key at $64aec, as $79360-$14874 at $611e8). At run time a site whose value lies
outside $e700-$80000 is left alone: the TNT patch points some of them into ExpMem.

The verify build read- and write-protects the chip copy, less the chip memory above
(`resload_ProtectReadWrite`, which needs WHDLoad's `MMU` option on a 68030 or better): an
access through a reference the table misses faults with the accessor's address.

## The enhanced framerate (Unleashed)

Behind the copy the slave puts the Unleashed blob (`src/unleashed.s`): Stunt Car Racer
Unleashed 1.1's routines, by Vesa Halttunen, with their labels and comments, and a table of
84 patches that writes each instruction Unleashed changed, or a `jmp`/`jsr` to the routine
that replaces it, over the copy. `tools/ulblob.py` assembles it twice to find its 307
relocations (the slave applies them with the copy's distance) and checks every patch
against the original's instruction boundaries and branch targets. What it reserves (its
variables and the 32000-byte fast render buffer) follows its code in ExpMem.

What it changes, as Unleashed does:

- The main loop runs one physics step per field that went by instead of one per six fields,
  each step a sixth as long (the 22 `move.b #$ee` time steps become $27), and the counters
  and cooldowns that count steps are scaled to match: about 50 frames a second on a fast
  machine at the original game speed.
- The 3D view is drawn into the fast render buffer and copied into the chip frame buffer at
  the end of the frame; the frame buffers swap in the VBlank interrupt, not in a copper
  interrupt at line $fa.
- `plotPixel` and `applyBitplaneMask` jump into tables instead of modifying their code, and
  the infinite boost is a flag (`ulRefreshBoost`, F6 and CUSTOM1) instead of a changed `bcs`.

Beyond Unleashed:

- The copper list ($e74e) starts with a wait for line 8 (at $e74a, over the chip original's
  start-up `jmp`, which never runs; COP1LC set at $ee44). Unleashed's own list has that
  wait; without it the copper loads the bitplane pointers before the VBlank interrupt swaps
  them, the new frame shows a field late and the copy tears its bottom lines.
- At $6a0ea the `lsr.l #3` of a sign-extended x that takes a left edge off the screen
  becomes `asr.l #3`: the original relies on the 24-bit address wrap, which fast memory
  above $1000000 does not have. The slave's two 24-bit masks ($69fea, $6a06e) are not
  applied to the copy, and the TNT patch's masks there are undone, so the fast render
  buffer's address survives.
- The key tables at $1b898 and $1b950 are read through `lea`, not through the chip copy's
  pointers.

Without the copy (no CUSTOM3, a 68000 or no ExpMem) the game runs its original loop.

## Slave patches

Addresses are the program's runtime addresses ($e700 + file offset of the decrypted main
program).

| Address | Patch |
|---|---|
| intro +$5a | a delay before the title picture removed |
| intro +$86 | black screen instead of red |
| intro +$f8 | level 2 interrupt (keyboard) installed by the slave |
| intro +$124 | `_PatchMain` before the main program |
| intro +$570 | Rob Northen loader to `_Loader` |
| $e70e | the checksum skipped |
| $f036 | keyboard: quit key, F6 infinite boost, F7 turbo, Help wins the race |
| $59846 | the "insert disk" request removed |
| $5b6bc | fire skips the name entry (`Player`) |
| $5c960 | the copylock's result ($9cedcd02 to $24) |
| $5dac0, $64516 | turbo: the frame delay at $616d8 skipped, `TURBO` drawn in the panel (not with the copy) |
| $5f2f8 | the lap and track times saved to `StuntCarRacer.times` after a race |
| $62d1c | the times loaded to $7a61a instead of $7a21a |
| $62e86 | the game's loader to `_Loader` (save slots in `StuntCarRacer.save`) |
| $69fea, $6a06e | two 24-bit address faults fixed (not with the copy: the blob fixes them for any memory) |

`_RefreshBoost` (F6, CUSTOM1) toggles the `bcs` at $60836 that ends the boost, or with the
copy Unleashed's flag.

## Limitations

Without CUSTOM3 the game runs from chip memory at its original rate (about 8 frames a
second on PAL). With it the frame rate depends on the machine: 50 on the emulated 68030 and
68040 with fast memory (200 frames in 200 fields). Link play over the serial port is untested
with the copy; Unleashed does not support it.
