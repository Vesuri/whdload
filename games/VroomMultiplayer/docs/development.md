# Development

Only what differs from the repository's `docs/running.md` and `docs/building.md`.

## Inputs

`inputs.sha256` pins two archives, which `make unpack` installs side by side in `tmp/game/`:

| Archive | Installs | Slave |
|---|---|---|
| `VroomMultiplayer.lha` (whdload.de) | `VroomMultiplayerHd/`: installer, imager slave (no source), slave source (`.src/`), no game data | v1.6 (03.06.2006) |
| `VroomMultiPlayer_v1.6_2158.lha` (Retroplay) | `VroomMultiPlayer/`: `Disk.1`, `VroomMultiplayer.Slave` | v1.6, the same bytes |

The Retroplay `Disk.1` is the slave's "v1" (its boot block holds $3658 at $1F8). The "v2"
(NTSC) version is not among the inputs.

## The build

`src/VroomMultiplayerHD.asm` is the package's `.src/` file (the import commit has it
unchanged). The setup commit made these commented edits, after which it builds
byte-identically to the shipped slave:

- the date Barfly's `WDate` wrote into the info text, `(03.06.2006)`, is a string;
- Barfly's `DBRA.b` is `DBRA`;
- Barfly's encodings: `move.l #$8C,d0` as `moveq #$73,d0; not.b d0`, `move.b #$FF` as
  `st`, `clr.l d0` as `moveq #0,d0`, and the immediate forms `addi`/`andi`/`cmpi` where vasm
  would emit the Dn forms.

`VASM_FLAGS` stand in for Barfly's optimiser (`BOPT O+`), as in `games/Vroom`.

The fixes since then are in `src/fixes.i`, `src/smc.i` and `src/blitwait.i` (generated by
`tools/blitstarts.py`), Enhanced framerate in `src/enhanced.i`; `ws_Version` is 17
(`ws_config`). `make run`/`serve` add `CACHE` and `CUSTOM1=1` on a 68020 and up, as the
installed icon will, unless `ENHANCED=0` or `WHD_ARGS` sets `CUSTOM1` (`game.conf`).

## Driving it

`make serve WARP=1 WINDOW=none &`, then `make server CMD=...`. Left alone, the title runs a
demo race (San Marino) after about 25 s in warp on the a500.

`tools/vmp.py serve` (with the run options in the environment, `INSTANCE=` for a run of
one's own) adds `do` (fields, mouse and buttons, reads, waits on a long or on the VBL hook,
breakpoints, screenshots, with the CPU stopped), `race` (the boot to the menu), `hook`,
`bench` (fps from the next green light), `statelog` (the race state at every frame end or
pass, for games/Vroom's `tools/statecmp.py`), `frames` (a hash of every line of each drawn
frame, for games/Vroom's `tools/framecmp.py`), `shown` (frames that changed the screen on
display) and `span` (the emulated time between two addresses, in raster lines read from the
beam through the stub: exact, the breakpoints stop the emulation). `bench N now` starts at once (after
`race`, whose lights may be out by the time the race's VBL hook is seen); `race menu` starts
a race from the menu (after a race's scores and the right button). With fast memory the
race block runs from a copy: the commands read and break at block addresses in it (the
offset at $1D6, `internals.md`, "Fast memory"). Developer knobs
for A/B builds (`DEFINES_x=-D... make build BUILD=x`, then `SLAVE=`): `ENH_NOBLITSITES`,
`ENH_NOFMODE`, `ENH_NOGROUND`, `ENH_NOINTERP` (no frames between ticks). The first demo race (Adelaide, two views) is the
same race on every machine; the second (San Marino) has one view.
The title and the menu share the VBL hook $ADAC; a race's is $AE64. In the menu the left
button on START, held until the hook is $AE64, starts a race (about 500 fields).

## Tools

| Tool | Does |
|---|---|
| `tools/addrmap.py VROOM.bin VMP.bin map ADDR ...` | each Vroom address's Multiplayer address (`segs`, `data`, `cmp LO HI` for the alignment itself; `internals.md`, "The program against Vroom's"). The images: chip memory at $3658 of each game, `BOOT_BREAK=0x3658` and `gdb dump binary memory`, with `SLAVE=original` |
| `tools/blitstarts.py VMP.bin` | writes `src/blitwait.i` |
| `tools/blitsites.py VMP.bin` | writes `src/blitsites.i`: the blitter starts the game waits after itself |
| `tools/vmp.py` | the game server, above |
| `tools/reloc.py IMAGE PROFILE...` | the race block's relocation census for fast memory (games/Vroom's, with this game's block and tables); PROFILEs from `gdb monitor aprof start`/`stop FILE` on the aprof FS-UAE (`FSUAE=$FSUAE_APROF EXTRA_ARGS=--cpu=68040-NOMMU`) |

Vroom's `tools/smc.py` and `tools/smcscan.py` run on this game's traces and images as they
are (`python3 ../Vroom/tools/smc.py TRACE.bin ...`).

## Traps

- WHDLoad's dump files are hidden (`.whdl_*`); a run stopped with `quit` leaves none, so
  any is a real exit.
