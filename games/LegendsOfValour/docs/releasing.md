# Building release archives

Run `make dist` in this directory (or `make dist GAME=LegendsOfValour` at the root). It
builds the release slave and runs `tools/release.py` (`game.sh` `game_dist`). Requires
Python 3, the normal vasm/WHDLoad/NDK build dependencies, and `lha`/Lhasa for extraction
and CRC verification. No LHA compressor is needed: the two replacements use the standard
uncompressed `-lh0-` method.

Inputs (`make unpack ARCHIVES=<directory>` copies and verifies them, `inputs.sha256`) and
outputs, in the repository's ignored `dist/`:

| Input in `tmp/archives/` | Output in `dist/` |
|---|---|
| `LegendsOfValour.lha` | `LegendsOfValour-1.1b.lha` |
| `LegendsOfValour_v1.0_0837.lha` | `LegendsOfValour_v1.1b_0837.lha` |

The command rebuilds the plain release slave (`make slave` with no `VASM_EXTRA`) and checks
its version and two-option menu. It prepends `release/ReadMe` to each original ReadMe and
updates the original memory requirement. Original credits (CFou!'s) and installation notes
remain. Each archive retains exactly its original entry names and order. Only the Slave and
ReadMe entries are replaced; every other compressed record, including its metadata, is
copied byte-for-byte. In particular, the install archive's legacy `.src` file stays
unchanged.

Before publishing, both staged archives pass Lhasa's full CRC test, replacement
extraction comparisons, and unchanged-record/name/order checks. Outputs can be
regenerated; a successful run replaces earlier output archives. The two replaced records
carry the packaging time, so rebuilt archives differ only in those records' timestamps
and header checksums. Packaging does not launch the game or alter installed slaves,
preferences or emulator sessions.

All original/generated bytes remain local: staging and builds are in the ignored `tmp/`,
and `dist/` is ignored. Never commit or automatically upload either archive.
`release/slaves.sha256` records the release slave (`make check`, `make record`).
